# MILOFIT Arena — Android client

A Kotlin + Jetpack Compose client for the MILOFIT Arena server. It speaks the same
protocol as the web client (`docs/PROTOCOL.md`) and reads the same content files,
so a phone and a laptop can share one match.

> ### Verified: this module compiles, passes its unit tests and produces an APK
>
> The client was originally written in an environment with no Android SDK and no
> Gradle, so it shipped as a reviewed-but-never-compiled skeleton. It has since
> been built for real, with JDK 21, Gradle 8.11.1, AGP 8.7.3 and Android SDK
> Platform 35:
>
> ```bash
> cd android
> ./gradlew :app:testDebugUnitTest   # BUILD SUCCESSFUL — 8 tests, 0 failures
> ./gradlew :app:assembleDebug       # app/build/outputs/apk/debug/app-debug.apk (~10 MB)
> ```
>
> The test run includes the parity suite: the Kotlin `SimCore` reproduces a
> 600-tick trajectory and a jetpack-hover profile generated by the *JavaScript*
> core, so client-side prediction and the authoritative server are provably the
> same function.
>
> The Gradle wrapper (`gradlew`, `gradlew.bat`,
> `gradle/wrapper/gradle-wrapper.jar`) is now checked in and was itself used for
> those builds — you do not need Gradle installed.

## The Gradle wrapper

The wrapper is checked in — `gradlew`, `gradlew.bat`,
`gradle/wrapper/gradle-wrapper.jar` and `gradle/wrapper/gradle-wrapper.properties`
(pinned to Gradle 8.11.1). Use it directly; you do not need Gradle installed:

```bash
cd android
./gradlew :app:assembleDebug        # Linux / macOS / Git Bash
.\gradlew.bat :app:assembleDebug    # Windows PowerShell
```

If the wrapper jar is ever lost, regenerate it with any installed Gradle 8.x, or
open the `android/` folder in Android Studio, which offers to restore it. Note
that `gradle wrapper` needs a settings file in the directory — `settings.gradle.kts`
is checked in, so this works from `android/`.

`.gitignore` deliberately does **not** ignore the wrapper: it is what makes the
build reproducible for everyone else.

## Build and run

From `android/`:

```bash
# 1. unit tests — the Kotlin movement core vs the JavaScript one
./gradlew :app:testDebugUnitTest

# 2. build a debug APK
./gradlew :app:assembleDebug
# -> app/build/outputs/apk/debug/app-debug.apk

# 3. install on a connected device or emulator
./gradlew :app:installDebug
```

On Windows use `gradlew.bat` instead of `./gradlew`.

### Start the server first

The client needs a server to talk to:

```bash
cd ../server
npm install
npm start
```

The server prints every address it is reachable on, including the LAN ones:

```
  web client   http://localhost:8080/
  lan / phone  http://192.168.1.42:8080/   (ws://192.168.1.42:8080/ws)
  websocket    ws://localhost:8080/ws
```

### Pointing the app at the server

The join screen has a **Server** field, pre-filled per target:

| Target | Address to enter |
| --- | --- |
| Android **emulator** | `ws://10.0.2.2:8080/ws` (this is the default; `10.0.2.2` is the host machine as seen from the emulator) |
| **Physical device** on the same Wi-Fi | `ws://<your-pc-lan-ip>:8080/ws` |
| Production | `wss://your.host/ws` |

A bare `host:port` or `http://…` is accepted too; the field is normalised to a
`/ws` WebSocket URL.

#### Cleartext (plain `ws://`) is not allowed by default

Android blocks cleartext traffic since API 28. `app/src/main/res/xml/network_security_config.xml`
opts in `localhost`, `127.0.0.1` and `10.0.2.2` only. To test against a LAN
address, **add that exact IP as another `<domain>` line** — the file matches
hostnames, not subnets:

```xml
<domain includeSubdomains="false">192.168.1.42</domain>
```

For a public deployment serve `wss://` and delete both the file and the
`android:networkSecurityConfig` attribute in `AndroidManifest.xml`.

## How it fits together

```
app/src/main/java/com/milofit/arena/
├─ MainActivity.kt          single activity; immersive landscape; hands off to ArenaApp
├─ data/
│  ├─ Models.kt             kotlinx-serialization mirrors of shared/game-data/*.json
│  └─ Content.kt            loads the pack from APK assets, builds id→object maps
├─ net/
│  ├─ Protocol.kt           wire message types, flags, defensive parsing
│  └─ GameClient.kt         OkHttp WebSocket: reconnect, ping, message fan-out
├─ game/
│  ├─ SimCore.kt            ← the port of shared/sim-core.js. Double everywhere.
│  ├─ Predictor.kt          local prediction + reconciliation (port of web/src/predict.js)
│  └─ GameViewModel.kt      socket owner, snapshot buffer, interpolation, frame loop, HUD state
├─ audio/Sfx.kt             PCM synthesis into one AudioTrack. No audio files.
└─ ui/
   ├─ Theme.kt              hex-string → Color, the UI palette
   ├─ Sprites.kt            procedural world / soldier / gun / effect drawing
   ├─ Controls.kt           two thumb sticks + button cluster
   ├─ Overlays.kt           menu, lobby, HUD, scoreboard, chat
   └─ ArenaApp.kt           one Canvas + a vsync frame loop, overlays on top
```

### The rules that keep it working

**1. `Double` for every simulation and network number, never `Float`.**
JavaScript numbers are IEEE-754 doubles. Kotlin `Float` is 32-bit and rounds
differently, so a `Float` simulation would drift away from the server over
hundreds of ticks and the client would rubber-band. Conversion to `Float` happens
only at the drawing boundary (`toFloat()` at the `Canvas` call).

**2. `SimCore.kt` must mirror `shared/sim-core.js` line for line.**
The two are maintained by hand, so a test enforces it:

```
app/src/test/java/com/milofit/arena/SimCoreTest.kt
```

It replays a **600-tick trajectory generated by the JavaScript core** — same
inputs, same map, same tuning — and asserts the Kotlin body lands within
**0.05 px** of the recorded end state (x, y, vx, vy, aim, facing, onGround,
jetFuel, jetIdle). A tolerance rather than bit-exact equality because Kotlin's
`Math.pow` may differ from V8's by an ULP. It also covers the jetpack hover rule,
one-way platforms, run-speed clamping and an arena-bounds fuzz. Change
`shared/sim-core.js` and this test fails until `SimCore.kt` follows.

**3. The data is not copied into this module.**
`app/build.gradle.kts` registers a `Copy` task (`copyGameData`) that fills
`build/generated/gameData` from `../shared/game-data` and adds it as an assets
`srcDir`. Editing the JSON in `shared/` is all it takes — there is exactly one
copy of the content in the repository.

**4. Per-frame state is not Compose state.**
Body positions, camera, effects and bullets change 60 times a second. Putting
them in `mutableStateOf` would trigger 60 recompositions a second. They are plain
fields on the ViewModel, read from inside a single `Canvas` draw pass that is
invalidated by one `mutableLongStateOf` frame counter.

**5. Every sound is synthesised at runtime.**
`audio/Sfx.kt` renders its waveforms into `ShortArray`s with a seeded xorshift
noise source, mixes up to 32 voices plus a looping jetpack into a 1024-sample
chunk, and streams them into one `AudioTrack` (22 050 Hz, mono, `MODE_STREAM`)
from a writer thread. If `AudioTrack` cannot be created the whole thing degrades
to a silent no-op instead of crashing — audio must never be able to take the
match down.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| `Could not resolve com.android.tools.build:gradle:8.7.3` | no network, or a proxy in front of `google()` |
| `Unsupported class file major version` / `Unsupported Java` | JDK 22+. Point `JAVA_HOME` at JDK 17–21 |
| `SDK location not found` | no `ANDROID_HOME` / `local.properties`. Studio writes `local.properties` for you |
| `Failed to find Platform SDK with path: platforms;android-35` | install Android 35 in the SDK Manager |
| App connects, then says "Offline" | cleartext blocked: add your LAN IP to `network_security_config.xml` (see above) |
| App builds but the arena is empty | the `copyGameData` task did not run; check `app/build/generated/gameData` contains `index.json` |
| Movement rubber-bands constantly | `SimCore.kt` has drifted from `shared/sim-core.js`; run `:app:testDebugUnitTest` |
