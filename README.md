# MILOFIT Arena

An **original** top-down/side-view arena shooter with jetpacks, built as one shared
multiplayer game with **two first-party clients**:

| Piece | Stack | Folder |
| --- | --- | --- |
| Multiplayer server (authoritative) | Node.js 20+, `ws` | `server/` |
| Web client | HTML5 Canvas + ES modules, zero build step | `web/` |
| Android client | Kotlin + Jetpack Compose + OkHttp WebSocket | `android/` |
| Shared game data | JSON (weapons, characters, maps, tuning) | `shared/game-data/` |

Everything in `shared/game-data/` and every pixel the clients draw is **generated by
this project**. There are no third-party game assets — see
[Provenance & legal](#provenance--legal) below.

> **Status:** all three parts build and are verified. The server and web client run
> under Node; the Android client compiles, passes its unit tests and produces a
> debug APK. See [Tests](#tests) for the exact commands and counts.

## Quick start

```bash
# 1. install server deps (only dependency is `ws`)
cd server
npm install

# 2. run it — serves the web client AND the websocket endpoint
npm start
# -> http://localhost:8080
```

Open `http://localhost:8080`, leave **Room** blank, choose the match options, and
press **Play**. The server creates a six-character room code shown in the in-game
header. Share that code; friends enter it in **Room** to join. The server serves
`web/` statically, so there is no web build step and no CORS setup.

Useful flags:

```bash
npm start -- --port 9000 --host 0.0.0.0   # LAN play
```

On a phone or another PC on the same network, open
`http://<your-lan-ip>:8080`. Enter the shared room code. The native Android app
uses `ws://<your-lan-ip>:8080/ws` as its server address. Host and join clients
share the same room regardless of whether they are web or Android.

Match formats are 1v1, 2v2, and 4v4 (2/4/8 slots). Roles are on by default for
1v1/2v2, with Raider selected by default; 4v4 defaults to role-free attackers.
The host can choose Normal, Lunar, or Zero-G gravity before play. Web input
supports keyboard/mouse, touch joysticks, and the browser Gamepad API (including
Xbox-style controllers where the browser exposes them).

## Controls

**Desktop**

| Action | Key |
| --- | --- |
| Move | `A` / `D` (or `←` / `→`) |
| Jump | `W` / `Space` |
| Jetpack | hold `W`/`Space` while airborne |
| Aim | mouse |
| Fire | left click (hold for automatic weapons) |
| Melee | `Q` or middle click |
| Throw grenade | right click or `F` |
| Switch weapon | `1` / `2` or mouse wheel |
| Reload | `R` (also automatic when empty) |
| Scoreboard | hold `Tab` |
| Chat | `Enter` |

**Android** — left thumb stick moves, right thumb aims and fires, tap the jetpack
button to boost, side buttons for melee / grenade / reload / swap.

## Playing across platforms

Both clients speak the same protocol (documented in
[`docs/PROTOCOL.md`](docs/PROTOCOL.md)) and share the same tuning constants from
`shared/game-data/tuning.json`, so a phone and a laptop can share a match. The
server is authoritative: clients only send inputs, never positions.

## Tests

All three parts are verified. From the repository root:

```bash
node server/test/sim.js      # 193 assertions — movement, weapons, damage, maps, roles, gravity, match flow
node server/test/smoke.js    #  42 assertions — HTTP, websocket handshake, path traversal
node server/test/ctf.js      #  36 assertions — LAN room codes, 4v4 capacity, CTF over real sockets
node web/test/client.js      #  66 assertions — protocol models, prediction parity, artwork, HUD math
```

`npm test` runs all four; all 337 assertions pass. `server/test/ctf.js` boots a
real server, creates a shareable room code, checks role-free 4v4 capacity, then
verifies the CTF capture limit and flag snapshots over real sockets.

The Android module has its own suite — eight tests, five of which are parity
checks against the JavaScript core (see [`android/README.md`](android/README.md)):

```bash
cd android && ./gradlew :app:testDebugUnitTest   # 8 tests, 0 failures
```

## Development notes

* **Server**: `npm run dev` starts it with `--watch`, so editing gameplay code
  restarts the sim. The sim is deterministic-ish (fixed 60 Hz step with an
  accumulator) which keeps client prediction close to the server.
* **Web**: plain ES modules. Edit and refresh; no bundler.
* **Android**: Kotlin + Compose, same protocol and same content files as the web
  client. It compiles, passes eight unit tests (including five parity checks
  against `shared/sim-core.js`) and builds a debug APK. Needs JDK 17–21 (not 22+)
  and SDK platform 35. Build steps and the troubleshooting list are in
  [`android/README.md`](android/README.md).

## Provenance & legal

MILOFIT Arena is an original work. It is **inspired by** the side-view
jetpack-arena genre, but it is not a port, rip, or redistribution of any
existing commercial game:

* No assets, maps, code, strings, or data files were extracted from another
  game. Every weapon, character, map, and sound is authored here.
* Character artwork is drawn procedurally at runtime from palette data in
  `characters.json`, so there are no borrowed sprites.
* Weapon names and statistics in `weapons.json` are original to this project.

Do not add third-party assets to this repository without a licence that permits
redistribution, and do not ship a build derived from someone else's APK.
